# ZMF VOX STUDIO+ (v0.1)

An installable, mobile-first PWA for making AI singing covers **entirely on your device**:
import a song → separate vocals → convert the vocal with a neural voice model you are
authorised to use → edit pitch, add harmonies, mix, master → export WAV/MP3.

No server, no account, no API keys, no uploads. Static files only; neural inference runs in
your browser with ONNX Runtime Web (WebGPU when available, WebAssembly otherwise).

> **No model weights are shipped.** You import openly licensed / authorised ONNX models once;
> they are stored on the device (OPFS, IndexedDB fallback) and verified by SHA-256.
> See [MODELS.md](MODELS.md).

## Quick start

```bash
cd vox
npm install
npm run dev          # http://localhost:5173 (sends COOP/COEP so WASM threads work)
npm test             # 36 unit/integration tests (Node + onnxruntime-node)
npm run test:e2e     # builds, then drives the production build in headless Chromium (10 tests)
npm run build        # static site in vox/dist
```

"Synthetic graph" means a tiny ONNX file generated by the tests with exactly the input/output
names, shapes and dtypes of a real model (e.g. the RVC test "voice" is a sine oscillator driven
by `pitchf`). It proves the orchestration, tensors, chunking and runtime work end-to-end; it does
not prove voice quality. Real-model results must be checked with real, authorised models.

## Architecture

```
src/audio/      pure TypeScript DSP (testable in Node): wav, resample, fft/stft, f0 (YIN),
                analysis (BPM/key/LUFS/true-peak), dsp effects, psola, notes, mixer,
                humanvoice, postconvert, centerExtract, mp3, voiceAnalysis, playback (Web Audio)
src/ml/         ONNX adapters: rvc.ts, mdx.ts (runtime-agnostic), worker.ts (ORT Web in a
                Web Worker), engine.ts (LRU session limit, cancel), modelStore (OPFS/IDB+SHA-256),
                caps.ts (measured capabilities)
src/dsp/        DSP worker (mix render, separation fallback, harmonies, edit render, analysis)
src/pipeline/   cover.ts (conversion orchestrator + measured evidence), separate, harmony, editRender
src/project/    types, defaults, .zvox and .zsinger file formats
src/pages/      13 screens · src/ui/ components (Waveform, Timeline, PianoRoll, Meter, Player)
```

Adding another voice-conversion architecture: implement a function with the shape of
`runRvc(ort, sessions…, x16, params, ctl)` in `src/ml/`, add a signature detector next to
`rvcSignature`, route it in `worker.ts`, and add a `SingerMode`.

## Deploy for free (static)

See [docs/DEPLOY.md](docs/DEPLOY.md) — GitHub Pages, Cloudflare Pages, Netlify. Any static host
works; COOP/COEP headers are optional (they enable multi-threaded WASM; without them the app
uses single-threaded WASM automatically).

## Responsible use

Only use voices you own or have explicit permission to use. The app ships no celebrity or
third-party voices, requires a permission confirmation when importing models and creating
singers, and labels exports as AI-generated by default.
